THIRD-PARTY SOFTWARE NOTICES AND INFORMATION

CodeBrix.Ollama is a pair of .NET libraries for downloading, managing and
running large language models in-process: CodeBrix.Ollama.ModelManager (a model
store and registry client) and CodeBrix.Ollama.ModelRunner (a managed binding
over a self-built native inference library). As of 2026-09-15 the repository
holds the native build tooling and the first native library; the managed
libraries are not yet written, and this file will grow entries for the code
they port (from the Ollama server, LLamaSharp and possibly OllamaSharp - all
MIT) when that happens.

Two distinct things in this repository come from other people today, and both
are covered below:

  1. THE VENDORED SOURCE. llama-native-tools/llama.cpp/ is an unmodified
     snapshot of the build-sufficient subset of the upstream llama.cpp source
     tree (which contains the ggml tensor library), committed to this
     repository so the native libraries can be rebuilt from it alone, years
     from now, with no dependency that may have disappeared. It is the only
     source the native libraries are ever built from.

  2. THE SHIPPED BINARIES. The package's runtimes/<rid>/native/ folders under
     src/CodeBrix.Ollama.ModelRunner/ contain libcodebrix_llama.dylib /
     libcodebrix_llama.so / codebrix_llama.dll compiled from exactly that
     source, one per runtime identifier (osx-x64 as of 2026-09-15; six more
     to come).

Both are governed by the licences reproduced in full below. Every one of them -
MIT, and the Apache License 2.0 (with and without the LLVM exception) - is
permissive and compatible with this repository's own MIT licence.

HOW THE MIT LICENCE'S NOTICE REQUIREMENT IS SATISFIED
    The MIT licence requires that "the above copyright notice and this
    permission notice shall be included in all copies or substantial portions
    of the Software". Every build script in llama-native-tools/ copies
    llama.cpp's own LICENSE file into its output folder as LICENSE-LlamaCpp.txt,
    and the adoption step copies it into runtimes/<rid>/native/ beside the
    binary. So the licence text physically travels inside the NuGet package,
    next to every native library, on every platform - in addition to this file.

WHAT WAS COPIED FROM UPSTREAM, AND WHAT WAS NOT
    Six top-level paths, complete and unmodified: CMakeLists.txt, LICENSE,
    cmake/, ggml/, src/, include/ - 1,467 files, about 25 MB. The rest of the
    upstream tree (common/, vendor/, tools/, examples/, tests/, docs/, models/,
    gguf-py/, scripts/ and the others - about 140 MB, including 75 MB of
    vocabulary files derived from third-party models) is not needed to build
    the library and was deliberately not copied. The exact copy command and
    the full list of what was excluded are in llama-native-tools/llama.cpp/
    UPSTREAM.txt. Because it is a subset, this file inventories what IS here,
    not the whole upstream project.

WHAT WAS MODIFIED
    NOTHING. Not one vendored file has been edited, renamed, reformatted or
    deleted. One file was ADDED, and it is a new file rather than a change to
    an existing one: llama-native-tools/llama.cpp/UPSTREAM.txt, which records
    where the snapshot came from. llama-native-tools/patches/ exists for the
    day a build needs a source change - applied at build time to a scratch
    copy, never to the snapshot - and as of 2026-09-15 it is empty. If a patch
    is ever added, this section must say so, because a patched binary is no
    longer plain upstream llama.cpp.

    The shipped binary does contain ONE translation unit that is not
    upstream's: llama-native-tools/wrapper/codebrix_llama.c, two functions
    that report the build's identity. It is original content of this
    repository and is not third-party.

WHAT IS NOT THIRD-PARTY, AND IS DELIBERATELY ABSENT FROM THIS FILE
    llama-native-tools/test-vectors/codebrix-conformance-tiny.gguf - the
    synthetic model the build gate runs. It is random weights from a fixed
    seed, generated in this repository on 2026-09-15 by
    llama-native-tools/test-vectors/generate-test-model.c. There are no
    trained weights, nothing derived from anyone's model, no vocabulary, and
    nothing downloaded. It is original content of this repository, and listing
    it here would be a false statement about its origin.

    The models that CodeBrix.Ollama downloads AT RUN TIME on a user's machine
    (and the SmolLM model the test suite will download when its live tests are
    enabled) are not part of this repository or its packages and are governed
    by their own licences.

NuGet package dependencies are not listed here; this file covers source code and
binaries incorporated INTO this repository. (Both libraries are planned to have
none.)

WHAT IS COMPILED INTO THE SHIPPED BINARIES
    From src/ and include/: the llama library - model loading (GGUF), the
    tokenizers, the KV-cache and graph code for every supported model
    architecture, sampling, grammars, chat-template matching, LoRA adapters.
    From ggml/: ggml-base and ggml (the tensor core and backend registry),
    ggml-cpu (including the llamafile tinyBLAS kernels and the YaRN routine),
    ggml-blas (macOS only, over Accelerate), ggml-metal (osx-arm64 only,
    including its Metal shader source embedded in the dylib; it too carries
    the YaRN routine).

WHAT IS PRESENT IN THE SNAPSHOT BUT NOT COMPILED INTO ANY SHIPPED BINARY
    * ggml/src/ggml-cuda, ggml-sycl, ggml-vulkan, ggml-opencl, ggml-hexagon,
      ggml-cann, ggml-webgpu, ggml-openvino, ggml-musa, ggml-virtgpu,
      ggml-zendnn, ggml-rpc, ggml-blas on non-macOS, and the other backends
      under ggml/src/ - GPU and accelerator backends this package does not
      enable. Kept because removing them would make the snapshot no longer
      diffable against upstream, and so a backend can be switched on later
      without re-vendoring. The Apache-2.0 material in entry 2 lives entirely
      inside these never-compiled folders.
    * ggml/src/ggml-cpu/kleidiai/* - Arm's KleidiAI glue, compiled only when
      GGML_CPU_KLEIDIAI is ON, which this package keeps OFF (turning it on
      would also make CMake download the KleidiAI kernel sources, which the
      rule this repository's native tooling lives by forbids).
    * ggml/src/ggml-cpu/arch/{wasm,powerpc,loongarch,s390x}/ and the SpaceMiT
      RISC-V kernels - architectures and extensions this package does not
      target (riscv64 is built scalar).
    * cmake/download-models.cmake - inert; nothing in the subset includes it.

INVENTORY: HOW THIS FILE WAS COMPILED, AND HOW TO RE-CHECK IT
================================================================================
On 2026-09-15 the vendored snapshot was inventoried mechanically, not by
reading around in it. The snapshot holds 1,468 files (1,467 from upstream plus
the added UPSTREAM.txt); 59 of them carry a copyright notice.

STEP 1 - every distinct notice, with a count:

    cd llama-native-tools/llama.cpp
    grep -rhI -o 'Copyright[^"]\{0,90\}' . | sort | uniq -c | sort -rn

  Eleven distinct notice lines naming seven holders: The ggml authors, Intel
  Corporation (three year ranges), Codeplay Software Ltd., Arm Limited,
  Mozilla Foundation, and Jeffrey Quesnelle and Bowen Peng. Every one is
  listed in entry 1 (MIT) and, for Intel and Codeplay, entry 2 as well.

STEP 2 - which files carry a licence grant that is NOT MIT's "Permission is
hereby granted, free of charge":

    grep -rlI -E 'Apache License|Licensed under the Apache' .      -> 37 files, all ggml/src/ggml-sycl/
    grep -rhI -o 'SPDX-License-Identifier: *[A-Za-z0-9.+ -]*' . | sort | uniq -c
                                                                  -> 42 MIT, 39 Apache-2.0
    grep -rlI 'SPDX-License-Identifier: Apache-2.0' . | grep -v ggml-sycl
                                                                  -> the 2 ggml-openvino files
    grep -rlI 'Redistribution and use in source and binary forms' .   -> nothing (no BSD)
    grep -rlI 'Permission to use, copy, modify' .                     -> nothing (no ISC)
    grep -rlI -E 'GNU General Public|Lesser General Public|Mozilla Public' .
                                                                  -> nothing (no copyleft)
    grep -rlI 'Boost Software License' .                              -> nothing

  The 37 ggml-sycl files with Apache text all ALSO carry an MIT header (the
  42 MIT SPDX tags = 37 sycl + 4 kleidiai + ggml/include/ggml-sycl.h). Every
  Apache-tagged file is in a backend this package never compiles -> entry 2.

STEP 3 - words that look like other licences but are not:

    grep -rnI -i -E 'public domain|unlicense|CC0' .

  One real hit: src/llama-sampler.cpp line 3032, a comment saying the DRY
  sampler's Z-algorithm loop is "adapted from the public domain
  implementation" at https://github.com/ivanyu/string-algorithms - public
  domain code carrying no licence obligation, credited by upstream in the
  comment, and covered here by the llama.cpp MIT licence as upstream ships
  it. Every other hit is a hexadecimal constant containing "cc0" or an
  identifier containing "acc0"; none is a licence statement.

STEP 4 - inline credits that are not file headers:

    grep -rnI 'MIT licensed' .

  Four hits, all the YaRN routine (Quesnelle and Peng) - listed in entry 1.

STEP 5 - what is NOT there. No BSD, ISC, GPL, LGPL, MPL or Boost text anywhere
in the snapshot; no NOTICE file; no bundled third-party library sources (the
upstream vendor/ folder - cpp-httplib, miniaudio, nlohmann/json, stb, BoringSSL
- was deliberately not copied, and nothing in the subset includes it).

Re-run steps 1 to 5 after any change to what is vendored, and update this file
to match. An entry that is out of date is worse than no entry, because it looks
like a statement someone checked.
